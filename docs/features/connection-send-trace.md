# Personal Connection & Send trace

Fork-only, bounded diagnostics. In the personal build, category-only events are sent to the authenticated dashboard on the configured private server at `/api/plugins/mobile-telemetry/events` when a session-list poll finishes or the app returns to foreground. No background timer, upload while the app is closed, or third-party telemetry is involved. The receiver stores at most eight 1 MiB, mode-0600 daily segments and prunes records older than seven days. The dashboard's existing token gate protects POST and GET; read recent records with authenticated `GET /api/plugins/mobile-telemetry/events?limit=50`. Unknown fields and raw content are rejected server-side. Offline uploads are best effort with an in-memory queue, so force-quitting or a full queue can lose events; telemetry must never block chat.

Settings → Connection → **Copy Connection & Send diagnostics** copies a snapshot on tap. Review the clipboard before sharing. The buffer holds the latest 300 entries for this process only; it is not persisted on the phone. Restarting the app clears it. Each line contains a timestamp, slot generation, categorical event, optional random send UUID, and (for successful hydration) rendered transcript row count. For status diagnosis it also records the session ID, polled `is_active`, displayed Working flag, stop-baseline presence and decision reason. The exact session ID is necessary to compare the visible row with its server state. No profile name, URL, prompt, attachment data, token, or raw error enters the trace API. Row counts measure displayed rows, **not** independent prompt submissions.

`slotCleared`/`socketSuspended` indicate deliberate teardown; `socketClosed` indicates the connect stream ended and schedules reconnect. `sendAccepted` means the `prompt.submit` RPC acknowledged, **not** that the model turn completed or the prompt was persisted. `sendTimedOut`/`sendDisconnected` are unknown server outcomes; retrying manually may submit twice. `sendRejected` is a failure classification, not an idempotency guarantee. Attachment sends are traced across upload and submit as one attempt; slash/compress commands are not prompt submissions in this trace. A server-authoritative hydrate records the resulting rendered row count. A regression test verifies that a persisted user turn duplicated by `inflight.user` now paints once (with the inflight assistant seed preserved).

The existing Debug log remains visible in Settings for local inspection but is not part of Copy diagnostics or automatic uploads: decoded summaries can contain chat text and **must never be copied/exported** as telemetry. Tests cover ring-buffer order/capacity and the closed exported vocabulary. Device reproduction still needs the installed build and matching server evidence to establish causality.
